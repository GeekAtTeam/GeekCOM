# Qt / Tauri 性能基线结果（2026-09-21）

产品基线：`539d3a5`。两套程序均为 Release；测试工具为本轮新增的未提交文件。方法、限制与后续验收见 [测试计划](performance-test-plan.md)。

## 条件与完整性

- 同一 Linux 桌面会话顺序执行，每组 60 秒，96 字节 × 100 Hz，共 6,000 条、576,000 字节。
- 使用新建 PTY，没有访问真实 IMU。两种调试页均关闭自动清空，文本模式；Tauri 时间戳默认开启，Qt 默认关闭。
- 两种实现的历史容量、终端功能与观测接口不同，这是产品基线对照，不是纯框架跑分。
- 每组均发完 576,000 字节，发送端无背压；Qt RX 计数和 Tauri 状态栏 RX 均为 576,000 字节。计数一致不能证明所有字节内容正确。
- 单次基线，尚未完成三次复测、60 分钟持续测试、实机和接收中的输入测试。

## 文本可用延迟

下列单位均为 ms，包含 16 ms 定时观察的误差，不代表像素绘制时间。前后段分别为序号前 25% / 后 25%。

| 实现 / 模式 | P50 | P95 | 最大 | 前段 P95 | 后段 P95 | 观察到标记 |
|---|---:|---:|---:|---:|---:|---:|
| qt / debug | 144 | 305 | 392 | 80 | 345 | 6000 / 6000 |
| qt / terminal | 24 | 36 | 63 | 34 | 36 | 6000 / 6000 |
| tauri / debug | 504 | 1348 | 1854 | 237 | 1515 | 5656 / 6000 |
| tauri / terminal | 41 | 63 | 77 | 61 | 64 | 6000 / 6000 |

Tauri 调试页有 344 条标记未被采样器观察到，但 RX 总数完整。采样器只读取尾部最多 8,192 个字符；主线程长时间阻塞后批量显示可能越过该窗口。因此不能据此断言串口丢失了 344 条数据，也不能宣称显示内容已经逐字节验证。

## 调度与资源（辅助指标）

| 实现 / 模式 | 定时器间隔 P95 (ms) | RSS 求和峰值 (MiB) | CPU 约占单核 (%) |
|---|---:|---:|---:|
| qt / debug | 170.0 | 116.8 | 95.6 |
| qt / terminal | 32.0 | 93.0 | 38.6 |
| tauri / debug | 447.0 | 816.5 | 104.4 |
| tauri / terminal | 26.0 | 647.8 | 39.3 |

RSS 求和包含共享页重复计算，Tauri 还包含自动化辅助进程；测量本身也会增加内存和 CPU。不要直接用表中数值计算框架资源倍率。

停止发送后的 Tauri 断开观察耗时：调试页约 632 ms，终端约 58 ms，均含 WebDriver 往返。它们不是接收中的按钮延迟，也没有同口径 Qt 对照。

## 当前结论

- 复现了 Tauri 调试页随历史增长而变慢的问题，默认设置不满足建议的 P95 ≤ 100 ms 目标，不应现在替代 Qt。
- Qt 调试页同样出现历史增长后的退化；Qt 方案本身不能视为性能无缺陷。
- Tauri 终端在本组 9,600 B/s 文本输入下延迟较稳定，但比 Qt 终端多约几十毫秒。没有复现终端秒级积压；真实设备、ANSI 密集内容、输入交互等仍待测。
- 40 ms 轮询和全量历史格式化是候选开销；不能仅凭代码审查把所有耗时归因于 IPC 或 WebKit。关闭时间戳的对照见下文。

## 控制变量：关闭 Tauri 调试时间戳

同一 release 二进制、同样 96 B × 100 Hz、60 秒，使用 `--tauri-no-timestamps`。本组输入和 RX 计数也均为 576,000 字节，无发送端背压。

| 时间戳 | P50 (ms) | P95 (ms) | 最大 (ms) | 后段 P95 (ms) | 观察到标记 |
|---|---:|---:|---:|---:|---:|
| 开启（默认基线） | 504 | 1348 | 1854 | 1515 | 5656 / 6000 |
| 关闭 | 471 | 1295 | 1716 | 1363 | 5938 / 6000 |

仅关闭时间戳没有消除秒级延迟，不能把主要原因直接归结为时间格式化。由于各只测一次，小幅差异也不宜解释为确定的性能提升。下一步优先对调试页的全量历史渲染、滚动/布局做分段测量，并考虑可见区域渲染；终端则单独测 IPC 与 40 ms 轮询开销。本轮不修改这些产品行为。

原始结果：`test-results/performance-60s-no-timestamps/results.json`。此组未观察到的 62 个标记同样不能直接计为串口丢失。
